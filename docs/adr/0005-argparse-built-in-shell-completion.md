# 0005 — argparse built-in shell completion (bash, zsh, fish)

Shell completion is generated by calling `parser.get_bash_complete()`, `parser.get_zsh_complete()`, and `parser.get_fish_complete()` on the gww argparse parser — no extra dependency, no hand-written shell scripts. `gww init shell <shell>` writes the generated script to the platform-appropriate path. Dynamic values (branches, worktrees) are filled in by a small custom completer at TAB time.

## Considered Options

- **`argcomplete`** — Rejected: extra dependency, no native Fish support, requires per-shell opt-in at runtime.
- **`pyparam`** — Rejected: extra dependency, less common.
- **Hand-written shell completion scripts** — Rejected: duplicates the parser definition in three shell dialects; every CLI change would require syncing four files.

## Implementation Notes

- The `gww init shell <shell>` command picks the right `get_*_complete()` method based on the `<shell>` argument and writes the script to the platform-appropriate location:
  - bash: `~/.bash_completion.d/gww`
  - zsh: `~/.zsh/completions/_gww` (or `$fpath/_gww`)
  - fish: `~/.config/fish/completions/gww.fish`
- Dynamic completers (branches, worktrees) must be fast — TAB responsiveness is the entire point of completion. Cache branch/worktree lists if measurement shows the queries are slow.
- Test completion behavior with realistic argument combinations (positional, optional, with `--tag`).

## Comparison

| Approach | Pros | Cons |
|---|---|---|
| **argparse built-in** | no deps, multi-shell, standard | manual script generation |
| **argcomplete** | dynamic, well-maintained | no Fish support, runtime setup |
| **pyparam** | flexible, Fish support | extra dependency |
| **Custom shell scripts** | full control | more maintenance, shell-specific |
